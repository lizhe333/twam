# HDMI / insert_hole 真值辅助恢复采集

批次配置：`configs/recovery_oracle_50.yaml`。输出：`data/recovery_oracle_v2/`。
目标为 HDMI 25 条、insert_hole 25 条恢复成功；旧 HDMI 3000001/attempt-05 计入目标。
只采集和整理，不训练，不修改现用训练清单。

## 启动和恢复

从仓库运行：

```bash
bash scripts/collect_recovery_oracle.sh --dry-run
bash scripts/collect_recovery_oracle.sh
```

包装脚本使用模型环境运行监督器和 AnyTouch，原生仿真由 `sim.sh` 使用仿真环境运行。
两个任务在单 GPU 上串行交替。进程锁防止重复启动，GPU 锁与已有评测入口兼容。
同一个命令恢复已有批次，已经保留的 seed 和失败尝试不退回额度。
参数和 checkpoint 固定；代码修复以追加源码版本记录，不能借重启清零额度。

## 执行与标签

自然 WAVE-0 使用双视角、10k EMA，预测 50、执行 10，每动作两个物理步；原生成功允许最后动作仅执行一个物理步。
完整分支预算 HDMI 600、hole 317，均包括自然前缀。教师通过原生 IK 和机器人控制接口行动。
自然策略最终成功时绝不恢复；失败时，仅恢复同一次仿真的持续受阻快照。

受阻检测逐动作读取物体真实进度、已下发命令、原生表面与触觉，在十步边界确认。
单块物体进展达到 `max(min_command_mm, resumed_progress_mm, progress_ratio × commanded_mm)` 才清除旧候选。
当前绝对下限为 0.2 mm；0.04–0.08 mm 的慢速蠕动不能单独证明受阻解除。
自然分支最终成功时仍绝不接管。快照恢复校验关节、物体、插槽、夹持与原生几何，不要求像素完全一致。
hole Teacher 使用原生倾斜目标和实际夹持变换，并确认卸载净空后再旋转。

每条成功恢复保留 N 个动作和 N+1 个观测。前缀只作上下文与 WM 转移；有效 Teacher 决策区间提供 BC 标签。
每次反馈决策结束即截断策略目标，排除的未来动作在进入训练输入前替换。
触觉窗口始终为 `[t-6,t-4,t-2,t]`，不足处复制首帧，接管时不清空历史。
真值只保留在原始记录和审计中，生产数据加载器不向学生传递。

## 结果

- `index.html`：两个任务的数量、所有尝试结果与样本链接。
- `manifests/<task>/recovery.jsonl`、`normal.jsonl`：独立恢复和正常对照清单。
- `review/<task>/<kind>/<seed>/`：失败/恢复配对视频、逐帧页面、加载与边界检查、样本契约。
- `<task>/attempts/<seed>/`：原始轨迹、自然分支、恢复分支、物理恢复检查及完整停止原因。
- `campaign.json`：原子持久化账本；`daemon.json`：监督器 PID 和状态。

合格样本标记 `suitable_for_imitation=true`、`training_enabled=false`。这表示技术上可用于模仿学习，不能据此声称学生已学会使用触觉。
自然 rollout 上限为 HDMI 200、hole 600；恢复分支分别 100。达到各 25 条或对应额度耗尽即结束，不添加人为偏移。

显式补采被检测器漏掉的 seed：修复代码并记录版本后，可使用
`--revisit-missed insert_HDMI:4000003 --revisit-missed insert_HDMI:4000004 --max-attempts 2`。
此入口只接受曾确认过受阻、最终失败且从未尝试恢复的完成记录，每个 seed 只允许补采一次。
在 `revisit-01/` 重新运行原版 WAVE-0 并从本次仿真快照恢复，旧结果保留在原目录和账本 `prior_attempts`。
新自然运行与恢复均照常扣额度，不自动重试失败恢复，也不重复计入成功数量。
在输出根目录创建 `STOP_AFTER_CURRENT`，新版监督器会在当前尝试和导出完成后停止；恢复前移除该标记。

## 实现检查

CPU 测试覆盖两任务几何、接触净空、持续受阻、正常进展与瞬时信号、N/N+1 前缀、标签/历史、任务归一化、并发账本和重启额度。
已有失败 3000001 的离线检查在第 50 步确认受阻。修复候选清除规则后，正常成功 3000002 的候选在第 450 步清除；自然成功始终不接管。
4000003/4000004 的第 60 步候选不再被 0.078/0.046 mm 的蠕动清除，正常成功 4000001 仍在第 120 步清除候选。
上述检查只读取已存轨迹，没有额外仿真回放，也没有渲染器消融。
